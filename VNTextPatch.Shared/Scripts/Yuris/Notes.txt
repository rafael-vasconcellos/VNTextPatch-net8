=====================================
Expression VM
=====================================
Apart from the scenario VM, YU-RIS has a tiny stack-based expression VM.
Each instruction consists of an opcode byte followed by a 16-bit argument length.

21 00 00                notequal
25 00 00                mod
26 00 00                logand
29 01 00 00             performvarindexation (uses all the stack values since the last "preparevarindexation" instruction as indexes)
2A 00 00                mul
2B 00 00                add
2C 00 00                nop (array index separator)
2D 00 00                sub
2F 00 00                div
3D 00 00                equal
3C 00 00                less
3E 00 00                greater
41 00 00                binand
42 01 00 XX             pushint8
46 08 00 XX{8}          pushdouble
48 03 00 24/40 XX XX    pushscalarvar
49 04 00 XX{4}          pushint32
4C 08 00 XX{8}          pushint64
4D XX XX 22 ... 22      pushstring (quoted string with support for \\, \n and \t escape codes, but not \" or \')
4F 00 00                binor
52 00 00                changesign
53 00 00                le
56 03 00 24 XX XX       preparevarindexation
57 02 00 XX XX          pushint16
5A 00 00                ge
5E 00 00                binxor
69 00 00                tonumber
73 00 00                tostring
76 03 00 24/40 XX XX    pusharrayvar (used to specify @ARRAY() in e.g. VARINFO in SEARCH mode)
7C 00 00                logor

=====================================
Expression interpreter implementation
=====================================
YurisExpressionInterpreter currently evaluates only expressions whose result
can be derived entirely from constants:

Supported:
    42 pushint8
    46 pushdouble
    49 pushint32
    4C pushint64
    4D pushstring
    57 pushint16
    2B add (numeric addition, string concatenation, or constant $_CHR bytes)
    2D sub
    2A mul
    2F div
    25 mod
    52 changesign
    69 tonumber
    73 tostring
    56 preparevarindexation + 29 performvarindexation
       only for constant indices into the same variable, and only when
       the resulting byte sequence contains recognized YU-RIS control codes.

Expressions containing scalar/array variable reads, comparisons, logical
operators, dynamic indices, unknown opcodes, malformed instructions, or
non-string final values are intentionally not evaluated. They remain
untranslated rather than being guessed or partially interpreted.

=====================================
YSVR parser implementation (ysv.ybn)
=====================================
YurisVariableScript parses YSVR records and exposes their original metadata.

Two observed record headers are supported:
    WithFlag:
        byte scope
        byte flag
        short scriptId
        short variableIndex
        byte valueType
        byte dimensionCount
    WithoutFlag:
        byte scope
        short scriptId
        short variableIndex
        byte valueType
        byte dimensionCount

The complete record stream is validated before a layout is accepted.
Known versions include a no-flag 7-byte header in a v474 sample and a
with-flag 8-byte header in v495/v555 samples. Version is only a tie-breaker
when both interpretations are structurally valid.

Scope:
    1 = global
    2 = local (associated with scriptId)
    3 = static

Value type:
    0 = declaration without initializer
    1 = Int64 initial value
    2 = Double initial value
    3 = length-prefixed expression bytecode

String expression bytes are preserved. EvaluatedStringValue is populated
only when the existing constant-expression interpreter can safely evaluate
the entire expression. Dynamic expressions are not modified or guessed.

=====================================
YSCD parser implementation (YSCom.ycd)
=====================================
YurisCompilerDefinitionScript parses the compiler language definition file:
    Header: YSCD, version, commandCount, unknown/padding
    Commands: NUL-terminated name, parameter count, parameter records
    Parameter: NUL-terminated name + four metadata bytes
    System-variable section: count + reserved word + variable declarations

Each system variable has a NUL-terminated name, value type, dimension count
and dimension sizes. The declaration order is its zero-based system-variable ID.

Command parameters preserve all four metadata bytes (Kind, Metadata1,
Metadata2 and Checker). Placeholder command entries such as ");" are retained
in Commands and excluded from ExecutableCommands.

Compiler settings, keywords and error-message strings are exposed as optional
metadata. DefinitionMetadata and TrailingData preserve the original unparsed
regions. The parser does not emit translation strings and never rewrites YSCD.

=====================================
Editable YSVR metadata export
=====================================
YurisVariableScript implements IStructuredScriptData. Extraction writes
ysv.json or ysv.jsonl (according to the selected output format) instead
of treating variables as dialogue strings.

Each variable has a stable ID:
    "{scope}:{flag}:{scriptId}:{index}"

Exported fields include:
    id, scope, scopeValue, flag, scriptId, index,
    type, typeValue, dimensions, value, isEvaluated,
    expressionBase64

The value property is editable:
    type integer          -> signed 64-bit JSON number
    type double           -> finite JSON number
    type stringExpression -> JSON string

A dynamic string expression that cannot be statically evaluated exports
value=null, isEvaluated=false and its original expressionBase64. Setting
value to a string replaces the complete initializer expression with a
constant pushstring expression. Leaving value as null preserves the original
expression byte-for-byte.

During insertion, only changed initializers are rewritten. Unchanged records,
headers, dimensions, flags, and trailing data are copied from the source YSVR.
The original binary is the baseline, so metadata not understood by the parser
is not discarded.

Note: YSCF caption (yscfg.ybn) is a separate configuration field and already
uses the normal text extraction/insertion path. It should be edited in
yscfg.json/jsonl; ysv.* is for actual global/local/static variable values.
